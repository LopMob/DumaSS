# Городская Дума — учёт депутатов, комиссий, заседаний и посещаемости

Минимальное веб-приложение (HTTP API + реляционная БД) для учёта депутатов
городской думы, комиссий, их председателей, заседаний и посещаемости.
Разработано как сквозной проект курса «Инфраструктура и Git-процесс»
(ЛР1) и будет развиваться в последующих лабораторных работах
(контейнеризация, CI/CD, очереди, Nginx, мониторинг).

## Технологии
- Python 3.12, FastAPI, SQLAlchemy 2.0, Alembic
- SQLite (по умолчанию, для ЛР1) / PostgreSQL (через `DATABASE_URL`)
- pytest, ruff, black

## Сущности и бизнес-правила
Депутаты, комиссии, членство в комиссиях (с признаком председателя),
заседания, посещаемость. Два содержательных правила предметной области:
1. У комиссии не может быть более одного действующего председателя.
2. Заседание нельзя закрыть («провести») без кворума — присутствовать
   должно больше половины членов комиссии.

Подробности: [`docs/TZ.md`](docs/TZ.md), [`docs/DATA_MODEL.md`](docs/DATA_MODEL.md).

## Быстрый старт
```bash
make setup      # venv + зависимости + .env из .env.example
make migrate    # применить миграции (создать таблицы)
make run        # запустить сервер на http://localhost:8000
```
Проверка работоспособности: `curl http://localhost:8000/health`
Интерактивная документация: `http://localhost:8000/docs`

## Конфигурация
Все настройки — через переменные окружения (см. [`.env.example`](.env.example)).
Файл `.env` создаётся из примера и **не коммитится** (см. `.gitignore`).

## Команды разработки
```
make setup     # первоначальная настройка
make run       # локальный запуск
make test      # автоматические тесты
make quality   # форматирование и статический анализ
make migrate   # применение миграций
make backup    # резервная копия БД
make restore   # восстановление БД
make verify    # полный набор локальных проверок (обязателен перед PR)
make up/down   # контейнерное окружение (задел на следующие ЛР)
```

## Git-процесс и правила внесения изменений
Обязательные проверки, запрещённые действия и порядок приёмки изменений
описаны в [`CONTRIBUTING.md`](CONTRIBUTING.md). Кратко: одна функция —
одна задача, одна ветка, несколько коммитов, `make verify` перед PR,
слияние через запрос на слияние, версии — тегами (`v0.1.0` — первая
версия).

## Структура репозитория
```
app/            — исходный код приложения (FastAPI, модели, схемы, роутеры)
alembic/        — миграции схемы БД
tests/          — автоматические тесты
docs/           — ТЗ, описание API, схема данных
Makefile        — единый командный интерфейс проекта
docker-compose.yml, Dockerfile — задел под контейнеризацию (следующие ЛР)
```
